# データベース設計

FlaskとPeeweeを使い、SQLiteの `instance/photo_share.sqlite3` に保存します。ユーザー、投稿、いいね、コメントの4つのテーブルを作ります。これは設計書であり、アプリ全体の動作確認の完了を示すものではありません。

## 決まったこと

- 表示名とユーザー名を分ける。表示名は重複でき、ユーザー名は重複できない。
- ログインにはメールアドレスとパスワードを使う。
- キャプションは任意で200文字以内。
- 自分の投稿にもいいねできる。1人が同じ投稿に付けるいいねは1件まで。
- 同じユーザーが同じ投稿に複数のコメントを書ける。
- 投稿を削除すると、写真ファイル、いいね、コメントも削除する。

## 1. ユーザー（User）

| 項目 | Peeweeの型 | 役割・ルール |
| --- | --- | --- |
| id | 自動採番の整数主キー | ユーザーを識別する番号 |
| display_name | CharField | 投稿やコメントに表示する名前。1〜30文字、重複可 |
| username | CharField | アカウントのID。半角英数字と `_` の3〜30文字、一意 |
| email | CharField | ログインに使うメールアドレス。254文字以内、一意 |
| password_hash | TextField | ハッシュ化したパスワード。平文は保存しない |
| created_at | DateTimeField | 登録日時 |

ユーザー名とメールアドレスは、前後の空白を除去して小文字で保存します。パスワードは8〜128文字で入力を確認し、ハッシュ化します。メールアドレスとパスワードのハッシュは他の利用者に表示しません。

## 2. 投稿（Post）

| 項目 | Peeweeの型 | 役割・ルール |
| --- | --- | --- |
| id | 自動採番の整数主キー | 投稿を識別する番号 |
| user | ForeignKeyField(User) | 投稿したユーザー。必須 |
| image_filename | CharField | `uploads/` 内の画像ファイル名。一意、必須 |
| caption | CharField | キャプション。200文字以内、未入力は空文字 |
| created_at | DateTimeField | 投稿日時 |

1つの投稿につき写真は1枚です。写真本体は `uploads/` に保存し、DBにはアプリが生成したファイル名だけ保存します。JPEG・PNG・WebP、10MiB以内であることと画像内容をアプリで検証します。写真の差し替えは行わず、キャプションだけ編集できます。

## 3. いいね（Like）

| 項目 | Peeweeの型 | 役割・ルール |
| --- | --- | --- |
| id | 自動採番の整数主キー | いいねを識別する番号 |
| user | ForeignKeyField(User) | いいねしたユーザー。必須 |
| post | ForeignKeyField(Post) | いいねの対象の投稿。必須 |

`user` と `post` の組み合わせに一意制約を付け、重複をDBでも防ぎます。いいねの取り消しは該当する行の削除で行います。件数は投稿ごとの行数から数え、Postに別の件数を保存しません。

## 4. コメント（Comment）

| 項目 | Peeweeの型 | 役割・ルール |
| --- | --- | --- |
| id | 自動採番の整数主キー | コメントを識別する番号 |
| user | ForeignKeyField(User) | コメントを書いたユーザー。必須 |
| post | ForeignKeyField(Post) | コメントの対象の投稿。必須 |
| body | CharField | 本文。前後の空白を除去し、1〜300文字 |
| created_at | DateTimeField | コメント日時 |

`user` と `post` の組み合わせには一意制約を付けません。同じユーザーが同じ投稿へ何度も書けます。本人のみ削除でき、コメント編集は今回作りません。

## テーブルの関係

| 親 | 子 | 関係 |
| --- | --- | --- |
| User | Post | 1人のユーザーが複数の投稿を持つ（1対多） |
| User | Like | 1人のユーザーが複数のいいねを持つ（1対多） |
| Post | Like | 1つの投稿が複数のいいねを持つ（1対多） |
| User | Comment | 1人のユーザーが複数のコメントを持つ（1対多） |
| Post | Comment | 1つの投稿が複数のコメントを持つ（1対多） |

Likeが「誰が、どの投稿にいいねしたか」を表します。SQLiteでの外部キーカラム名は `user_id`、`post_id` になります。

## 保存と削除のルール

- SQLiteの外部キー制約を有効にする。すべての外部キーに `ON DELETE CASCADE` を指定する。
- 投稿削除時はDBが関連するLikeとCommentを削除し、アプリが写真ファイルを削除する。
- アカウントの削除画面は今回作らない。
- 起動時に存在しないテーブルだけを作り、既存の投稿を初期化しない。
- DB接続はリクエスト開始時に開き、終了時に閉じる。
- 日時はUTCで保存し、画面では日本時間で表示する。投稿は日時とIDの降順で取得する。
- 必須入力や文字数はサーバー側で検証する。SQLiteではCharFieldの指定だけで文字数制限が強制されるとは考えない。
- DB・画像・パスワード・セッション署名キーをGitへ追加しない。
